~/labo

Variantes d'animations et de vue compétences pour la maquette terminal. [actif] = déjà branché dans DEV C, [option] = à ajouter ou à échanger si tu préfères. Chaque bloc se rejoue.

→ animations→ vues compétences→ retour à la maquette

// animations

A1 · boot systemdactif

Au premier chargement (une fois par session). Le [ WAIT ] glisse le message « je cherche une alternance » de façon ludique. Passable d'une touche.

A2 · commande tapée + impressionactif

À chaque changement de page : la commande se tape dans la barre, puis la sortie se déroule ligne par ligne.

A3 · décodage du titreactif

Sur MAFRAY-LIZÉ et sur le nom du projet ouvert dans le second terminal.

MAFRAY-LIZÉ
A4 · barres de progressionactif

Langues dans whoami.md. Pourrait aussi servir pour un « chargement » de page.

A5 · split tmuxactif

Le bouton « voir » d'un projet : le séparateur se trace, le panneau s'ouvre, puis le README s'imprime.

$ ls projets/
menucash/ voir ↗
A6 · spinner de chargementactif

Sur les captures du second terminal, le temps que les images chargent.

A7 · mode CRToption · bouton [crt]

Scanlines, vignettage, lueur et léger scintillement. Désactivé par défaut (lisibilité), activable dans la barre du haut.

$ whoami
MAFRAY-LIZÉ
Fullstack, IA & Data
A8 · réponse « sudo »actif

Easter egg classique : taper sudo dans l'invite. D'autres possibles : rm -rf /, hire lyam, coffee.

// vues compétences

S1 · tree + grepactif

Dossiers dépliables, filtre en direct (essaie « python » ou « ml »), et pour chaque outil l'endroit où il est prouvé : projet, expérience ou certif.

S2 · commandes par familleoption

Chaque famille est une commande : on clique, elle se tape et la sortie s'empile comme un vrai historique.

S3 · extraits de code (cat)option

Un extrait dépliable par famille. Montre le niveau réel plutôt qu'une liste. Combinable avec S1 (une ligne « cat exemple » par dossier).

S4 · tableau htopoption

Tous les outils dans un tableau triable (par nom, famille ou nombre de preuves).
